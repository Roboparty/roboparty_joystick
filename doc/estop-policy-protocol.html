① 认证协议（三步认证）一次性可靠传输

执行时机：连接建立后立即执行，认证成功后才能发送其他数据包。
🔄 认证流程
客户端 服务器 │ │ │ ① AuthRequest │ │ {device_id, device_name, timestamp} │ ├────────────────────────────────────────────→│ │ │ │ ② Challenge │ │ {challenge_code, timestamp} │ │←────────────────────────────────────────────┤ │ │ │ [计算 HMAC-SHA256(device_id:challenge)] │ │ │ │ ③ ChallengeResponse │ │ {device_id, signature} │ ├────────────────────────────────────────────→│ │ │ │ [验证签名，生成 Token] │ │ │ │ ④ AuthResult │ │ {ok, token, expires_at, reason} │ │←────────────────────────────────────────────┤ │ │ │ 认证成功，进入正常通信模式 ✓ │
📤 ① AuthRequest（客户端→服务器）
字段 类型 示例值 说明
typeString"auth_request"固定值
device_idString"android-a1b2c3d4"设备唯一标识（自动生成，持久化）
device_nameString"Android Gamepad"设备名称
timestampLong1699999999999请求时间戳（毫秒）
{ "type": "auth_request", "device_id": "android-a1b2c3d4", "device_name": "Android Gamepad", "timestamp": 1699999999999 }
📥 ② Challenge（服务器→客户端）
字段 类型 示例值 说明
typeString"challenge"固定值
challenge_codeString"e4d9f3b2a1c8..."随机挑战码（32 字符十六进制）
timestampLong1699999999015服务器时间戳
{ "type": "challenge", "challenge_code": "e4d9f3b2a1c876543210fedcba987654", "timestamp": 1699999999015 }
📤 ③ ChallengeResponse（客户端→服务器）
字段 类型 示例值 说明
typeString"challenge_response"固定值
device_idString"android-a1b2c3d4"设备唯一标识
signatureString"b3a8f2c1d4e5..."HMAC-SHA256 签名
签名算法：HMAC-SHA256("{device_id}:{challenge_code}", SECRET_KEY)
{ "type": "challenge_response", "device_id": "android-a1b2c3d4", "signature": "b3a8f2c1d4e56789012345678901234567890abcdef..." }
📥 ④ AuthResult（服务器→客户端）
成功响应：
{ "type": "auth_result", "ok": true, "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "expires_at": 1700003599999, "reason": "" }
失败响应：
签名验证失败或设备未授权时返回。
{ "type": "auth_result", "ok": false, "token": "", "expires_at": 0, "reason": "Invalid signature" }

② 控制指令 50Hz客户端→服务器

执行时机：认证成功后持续发送，每 20ms 一帧。
📤 ControlPacket
字段 类型 范围 说明
typeString"control"固定值
tokenString-认证令牌
timestampLong毫秒发送时间戳
sequenceLong单调递增序列号
left_stick_xFloat-1.0 ~ 1.0左摇杆水平（右为正）
left_stick_yFloat-1.0 ~ 1.0左摇杆垂直（下为正）
right_stick_xFloat-1.0 ~ 1.0右摇杆水平（右为正）
right_stick_yFloat-1.0 ~ 1.0右摇杆垂直（下为正）
btn_aBooleantrue/falseA 按钮
btn_bBooleantrue/falseB 按钮
btn_xBooleantrue/falseX 按钮
btn_yBooleantrue/falseY 按钮
dpad_upBooleantrue/false方向键上
dpad_downBooleantrue/false方向键下
dpad_leftBooleantrue/false方向键左
dpad_rightBooleantrue/false方向键右
{ "type": "control", "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "timestamp": 1699999999999, "sequence": 1, "left_stick_x": 0.5, "left_stick_y": -0.3, "right_stick_x": 0.0, "right_stick_y": 0.0, "btn_a": true, "btn_b": false, "btn_x": false, "btn_y": false, "dpad_up": false, "dpad_down": false, "dpad_left": false, "dpad_right": false }
传输方式：单向推送，无需响应。新帧覆盖旧帧，不保证到达。

③ 心跳保活 2Hz双向

执行时机：认证成功后持续发送，每 500ms 一次。
📤 心跳请求（客户端→服务器）
{ "type": "heartbeat", "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "timestamp": 1699999999999 }
📥 心跳响应（服务器→客户端）
服务器收到心跳后返回响应，用于连接保活检测。
{ "type": "heartbeat", "timestamp": 1699999999999 }

④ 急停请求 最高优先级可靠传输客户端→服务器

设计目标：语义明确、可靠传输、支持多种触发原因。
📤 Estop 请求包
字段 类型 示例值 说明
typeString"estop"固定值
tokenString"eyJhbGciOi..."认证令牌
timestampLong1699999999999时间戳（毫秒）
sequenceLong42序列号（用于匹配确认）
reasonString"user_triggered"触发原因
emergencyBooleantruetrue=紧急急停，false=普通停止
{ "type": "estop", "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "timestamp": 1699999999999, "sequence": 42, "reason": "user_triggered", "emergency": true }
📥 EstopAck 确认包
服务器收到急停后返回确认。
{ "type": "estop_ack", "ok": true, "timestamp": 1699999999999, "sequence": 42 }
📋 触发原因枚举
reason 值 说明
"user_triggered"用户手动触发（按 START 键）
"app_background"应用进入后台
"gamepad_disconnect"手柄断开连接
"heartbeat_timeout"心跳超时
"low_battery"设备电量过低
"policy_cancel"取消正在执行的策略
🔄 可靠传输机制
客户端 服务器 │ │ │ ① Estop (sequence=42) │ ├──────────────────────────────────→│ │ │ │ 等待 50ms │ │ │ │ ② EstopAck (sequence=42) │ │←──────────────────────────────────┤ │ │ │ 收到确认，急停成功 ✓ │ ─── 如果未收到确认，自动重试 ─── │ ① Estop (sequence=42) │ ├──────────────────────────────────→│ │ │ │ 等待 50ms，超时 │ │ │ │ ② Estop (sequence=42) [重试1] │ ├──────────────────────────────────→│ │ │ │ 等待 100ms │ │ │ │ ③ EstopAck (sequence=42) │ │←──────────────────────────────────┤ │ │ │ 收到确认，急停成功 ✓ │
重试策略：最多 3 次重试，间隔递增（50ms → 100ms → 200ms），总最大等待 350ms

⑤ Policy 请求 可靠传输客户端→服务器

设计目标：支持多种动作序列、可靠传输、支持查询和取消。
📤 Policy 请求包
字段 类型 示例值 说明
typeString"policy"固定值
tokenString"eyJhbGciOi..."认证令牌
timestampLong1699999999999时间戳（毫秒）
sequenceLong100序列号
policy_idString"go_home"策略标识
actionString"execute"动作类型
paramsObject{}策略参数（可选）
{ "type": "policy", "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "timestamp": 1699999999999, "sequence": 100, "policy_id": "go_home", "action": "execute", "params": {} }
📋 动作类型
action 值 说明
"execute"执行策略
"cancel"取消正在执行的策略
"query"查询策略执行状态
📋 预定义策略
policy_id 说明 params
"go_home"回到初始位置{}
"patrol"巡航模式{"route": "default"}
"follow"跟随模式{"target": "nearest"}
"stand_up"站起{}
"sit_down"坐下{}
"idle"待机{}
"calibrate"校准{"sensor": "all"}
"self_test"自检{}
"custom"自定义动作{"command": "..."}
📥 PolicyAck 确认包（立即响应）
服务器收到请求后立即返回确认，表示已接受请求。
{ "type": "policy_ack", "ok": true, "policy_id": "go_home", "sequence": 100, "timestamp": 1699999999999 }
📥 PolicyResult 执行结果包
成功：
{ "type": "policy_result", "policy_id": "go_home", "status": "completed", "result": { "distance": 5.2, "time_elapsed": 12.5 }, "timestamp": 1699999999999 }
失败：
{ "type": "policy_result", "policy_id": "go_home", "status": "failed", "error": { "code": 1001, "message": "Obstacle detected" }, "timestamp": 1699999999999 }
📋 执行状态枚举
status 值 说明
"pending"等待执行
"executing"执行中
"completed"执行完成
"failed"执行失败
"cancelled"已取消
📋 错误码定义
错误码 说明
1001障碍物检测
1002电量不足
1003传感器故障
1004超时
1005未知策略
🔄 完整交互流程
客户端 服务器 │ │ │ ① Policy (go_home, execute) │ ├──────────────────────────────────→│ │ │ │ ② PolicyAck (ok=true) │ │←──────────────────────────────────┤ │ │ │ 等待执行结果... │ │ │ │ ③ PolicyResult (completed) │ │←──────────────────────────────────┤ │ │ │ 策略执行完成 ✓ │ ─── 取消正在执行的策略 ─── │ ① Policy (go_home, cancel) │ ├──────────────────────────────────→│ │ │ │ ② PolicyAck (ok=true) │ │←──────────────────────────────────┤ │ │ │ ③ PolicyResult (cancelled) │ │←──────────────────────────────────┤ │ │ │ 策略已取消 ✓ │
重试策略：最多 3 次重试，ACK 超时 1000ms，执行结果最大等待 30s

⑥ 遥测数据（服务器推送）服务器→客户端

执行时机：服务器主动推送，客户端无需请求。
📥 电机状态 (10Hz)
{ "type": "motors", "timestamp": 1699999999999, "left_speed": 100.0, "left_current": 1.5, "left_temp": 35.0, "left_encoder": 12345, "right_speed": 100.0, "right_current": 1.5, "right_temp": 35.0, "right_encoder": 12345, "motor_error": 0 }
📥 IMU 数据 (50Hz)
{ "type": "imu", "timestamp": 1699999999999, "accel_x": 0.1, "accel_y": 0.1, "accel_z": 9.8, "gyro_x": 0.5, "gyro_y": 0.5, "gyro_z": 0.2, "roll": 2.0, "pitch": 2.0, "yaw": 180.0, "mag_x": 25.0, "mag_y": -10.0, "mag_z": 40.0, "imu_error": 0 }

📊 传输方式总结

数据包 方向 传输方式 频率 可靠性
Auth 双向 请求-响应 一次性 高
ControlPacket 客户端→服务器 单向推送 50Hz 低
Heartbeat 双向 单向推送 2Hz 低
Estop 客户端→服务器 重试+确认 触发时 高（3次重试）
Policy 客户端→服务器 确认+状态跟踪 触发时 高（3次重试）
MotorStatus 服务器→客户端 服务器推送 10Hz 低
ImuData 服务器→客户端 服务器推送 50Hz 低
优先级
最高优先级 │ ├── Estop（急停）← 最高 │ ├── Policy（策略） │ ├── ControlPacket（控制指令） │ └── Heartbeat（心跳）← 最低
