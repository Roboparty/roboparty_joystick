🎮 手柄控制器通信协议

三步认证 + Token 会话 + 心跳保活

📋 一、协议概述

手柄控制器与服务器之间采用 UDP 协议通信，实现以下核心功能：

  • 1三步认证 - HMAC-SHA256 签名验证设备身份
  • 2Token 会话 - 认证后获取 Token，后续通信携带
  • 3高频控制 - 50Hz 发送摇杆/按键数据
  • 4心跳保活 - 每秒发送心跳检测连接状态
  • 5断线重连 - 自动检测断线并尝试重连

🔐 二、三步认证流程

2.1 流程图

客户端 (手柄) 服务器 (机器人) │ │ │ ① AuthRequest │ │ { device_id, device_name } │ ├──────────────────────────────────────────→│ │ │ │ ② Challenge │ │ { challenge_code, timestamp } │ │←──────────────────────────────────────────┤ │ │ │ [计算 HMAC-SHA256(device_id:challenge)] │ │ │ │ ③ ChallengeResponse │ │ { device_id, signature } │ ├──────────────────────────────────────────→│ │ │ │ [验证签名，生成 Token] │ │ │ │ ④ AuthResult │ │ { ok: true, token, expires_at } │ │←──────────────────────────────────────────┤ │ │ │ 进入 CONNECTED 状态 │ │ 保存 Token │ │ │ │ ⑤ ControlPacket (50Hz) │ │ { token, timestamp, sequence, ... } │ ├──────────────────────────────────────────→│ │ │ │ ⑥ Heartbeat (每秒) │ │ { token, timestamp } │ ├──────────────────────────────────────────→│ │ │

2.2 签名算法

HMAC-SHA256 签名计算：
输入：deviceId:challengeCode
密钥：预共享密钥（SECRET_KEY）
输出：十六进制签名字符串（小写）
// 签名示例 输入: "android-abc123:a1b2c3d4e5f6" 密钥: "your-pre-shared-secret-key" 输出: "7f83b1657ff1fc53b92dc18148a1d65dfc2d4b1fa3..."

📦 三、数据包格式

3.1 认证请求 (AuthRequest)

客户端 → 服务器
{ "type": "auth_request", "device_id": "android-abc123", "device_name": "Xbox Controller", "timestamp": 1699999999999 }

3.2 挑战码 (Challenge)

服务器 → 客户端
{ "type": "challenge", "challenge_code": "a1b2c3d4e5f67890abcdef1234567890", "timestamp": 1699999999999 }

3.3 挑战响应 (ChallengeResponse)

客户端 → 服务器
{ "type": "challenge_response", "device_id": "android-abc123", "signature": "7f83b1657ff1fc53b92dc18148a1d65dfc2d4b1fa3..." }

3.4 认证结果 (AuthResult)

服务器 → 客户端
{ "type": "auth_result", "ok": true, "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "expires_at": 1700003599999, "reason": "" }

3.5 控制指令 (ControlPacket)

客户端 → 服务器 (50Hz)
{ "type": "control", "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "timestamp": 1699999999999, "sequence": 1, "left_stick_x": 0.5, "left_stick_y": -0.3, "right_stick_x": 0.0, "right_stick_y": 0.0, "btn_a": true, "btn_b": false, "btn_x": false, "btn_y": false, "dpad_up": false, "dpad_down": false, "dpad_left": false, "dpad_right": false }

3.6 心跳 (Heartbeat)

客户端 → 服务器 (每秒)
{ "type": "heartbeat", "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "timestamp": 1699999999999 }

📝 四、字段说明

4.1 ControlPacket 字段

字段 类型 范围 说明
type String "control" 数据包类型标识
token String - 认证令牌（三步认证后获取）
timestamp Long 毫秒 发送时间戳
sequence Long 单调递增 序列号，用于丢包检测
left_stick_x Float [-1.0, 1.0] 左摇杆水平轴（右为正）
left_stick_y Float [-1.0, 1.0] 左摇杆垂直轴（下为正）
right_stick_x Float [-1.0, 1.0] 右摇杆水平轴（右为正）
right_stick_y Float [-1.0, 1.0] 右摇杆垂直轴（下为正）
btn_a/b/x/y Boolean true/false ABXY 按钮状态
dpad_* Boolean true/false 方向键状态

🔄 五、连接状态机

5.1 状态说明

状态 说明 UI 显示
DISCONNECTED 未连接，初始状态 未连接
CONNECTING 正在建立 UDP 连接 连接中...
AUTHENTICATING 正在进行三步认证 认证中...
CONNECTED 已连接，正常通信 已连接
LOST 连接丢失（心跳超时） 连接断开
RECONNECTING 正在尝试重连 重连中...
FAILED 连接失败（不可恢复） 连接失败

📊 八、带宽计算

8.1 单个数据包大小

数据包类型 JSON 大小 UDP 开销 总大小
ControlPacket ~300 字节 46 字节 ~350 字节
Heartbeat ~150 字节 46 字节 ~200 字节

8.2 带宽需求

控制流（50Hz）：350 字节 × 50 = 17,500 字节/秒 = 140 kbps
心跳（2Hz）：200 字节 × 2 = 400 字节/秒 = 3.2 kbps
总计：约 143.2 kbps（0.14 Mbps）

8.3 周期配置说明

报文类型 频率 周期 说明
ControlPacket 50Hz 20ms 游戏手柄标准刷新率
Heartbeat 2Hz 500ms 快速检测断线，允许 10 次丢包

📶 十一、BLE 蓝牙通信协议

11.1 BLE 服务定义

Service UUID: 0000fff0-0000-1000-8000-00805f9b34fb ├── TX Characteristic: 0000fff1-0000-1000-8000-00805f9b34fb (客户端写入 → 机器人) └── RX Characteristic: 0000fff2-0000-1000-8000-00805f9b34fb (机器人通知 → 客户端)

11.2 BLE 连接流程

┌─────────────────────────────────────────────────────────────┐ │ BLE 连接流程 │ ├─────────────────────────────────────────────────────────────┤ │ │ │ ① 扫描 BLE 设备（按 Service UUID 过滤） │ │ ↓ │ │ ② 选择目标设备并连接 │ │ ↓ │ │ ③ 发现服务和特征 │ │ ↓ │ │ ④ 订阅 RX Characteristic 通知 │ │ ↓ │ │ ⑤ 协商 MTU（建议 512 字节） │ │ ↓ │ │ ⑥ 执行三步认证（与 UDP 相同） │ │ ↓ │ │ ⑦ 进入正常通信模式 │ │ │ └─────────────────────────────────────────────────────────────┘

11.3 BLE vs UDP 对比

特性 UDP BLE
传输距离 局域网（WiFi） 10-50 米
连接方式 需要知道 IP 地址 自动扫描发现
传输速率 高（>1Mbps） 中（~100Kbps）
功耗 高 低
延迟 低（<10ms） 中（~30ms）
适用场景 固定网络环境 快速配对、移动场景

11.4 BLE 数据分包协议

单包格式（数据 ≤ MTU-3 字节）：
直接发送 JSON 字符串的 UTF-8 字节
分包格式（数据 > MTU-3 字节）：
| 包头 (2字节) | 包序号 (1字节) | 总包数 (1字节) | 数据 (变长) |
| 0xAA 0x55 | 0x00~0xFF | 0x00~0xFF | JSON 字节 |

🧪 十二、测试服务器示例

12.1 Python 模拟服务器

#!/usr/bin/env python3 import socket, json, hmac, hashlib SECRET = b"your-pre-shared-secret-key" sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM) sock.bind(("0.0.0.0", 9000)) print("Server listening on port 9000...") while True: data, addr = sock.recvfrom(1024) msg = json.loads(data) print(f"Received from {addr}: {msg}") if msg["type"] == "auth_request": # ② 下发挑战码 challenge = { "type": "challenge", "challenge_code": "random1234567890abcdef", "timestamp": int(time.time() * 1000) } sock.sendto(json.dumps(challenge).encode(), addr) print(f"Sent challenge to {addr}") elif msg["type"] == "challenge_response": # ④ 验证签名 expected = hmac.new( SECRET, f'{msg["device_id"]}:random1234567890abcdef'.encode(), hashlib.sha256 ).hexdigest() if msg["signature"] == expected: result = { "type": "auth_result", "ok": True, "token": "test-token-xxx", "expires_at": int(time.time() * 1000) + 3600000 } else: result = { "type": "auth_result", "ok": False, "reason": "Invalid signature" } sock.sendto(json.dumps(result).encode(), addr) print(f"Sent auth result: {result['ok']}") elif msg["type"] == "control": print(f"Control: seq={msg['sequence']}, " f"left=({msg['left_stick_x']:.2f}, {msg['left_stick_y']:.2f}), " f"btn_a={msg['btn_a']}") elif msg["type"] == "heartbeat": # 回复心跳 sock.sendto(json.dumps({"type": "heartbeat"}).encode(), addr)
